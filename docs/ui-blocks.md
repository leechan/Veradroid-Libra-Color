# VeraHome “方块”界面风格（默认；可切回经典）

分支 `feat/ui-blocks`，VeraHome 0.28.0。起因：用户看了另一款墨水屏阅读器固件的视频，问我们的界面和功能能不能往那个方向走。
只借它的**交互方式和排布思路**（底部四个标签、方框卡片、黑底分组标题、步进器代替滑条、方块级别条、分页列表、阅读器底部六个按钮）；
名字、图标、图形、具体像素排布全部是我们自己的（图标在 `Icons.java` 里用线条画：FOLDER / USER / DEVICE / IMAGE / NOTE / LAYOUT / CLOCK / CALENDAR / WIDGET）。

## 怎么切换

设置 → 应用与桌面 → 外观 → **界面风格：经典 / 方块**（偏好键 `ui_style`，`classic` | `blocks`，默认 `blocks`，2026-11-14 起；以前没选过的人升级后也会变成方块）；方块风格里在 我的 → 显示与刷新 → 界面 里切回。
同一处还有 **英文小字** 开关（键 `ui_caps`，默认开）：每个中文标题上面那行小号英文（CONTINUE、THIS WEEK…）。
经典风格的一切（主页、书库、设置、面板）都没动；经典设置的每一项在方块风格里都有（每页最下面“更多…”和“设备与关于”里的入口，2026-11-14 起也是方块的样子，见“全部界面”）。

## 全部界面（方块风格下每一页从哪里进、是什么样子）

2026-11-14 第四轮：整个界面都改成方块的样子，方块风格下不再有经典样子的页面。经典风格的代码一行没删，切回经典一切照旧。

| 选择文件（别的应用要文件时） | 应用里的“选择文件” | **新**：方块页头、路径条、分页列表；返回方块 = 上一级 |
| 切换应用 | 面板快捷开关 / 四角长按 / 电源与时间 | **新**：双线框单子 + 英文小字标题，整页翻 |

耗时（同一台模拟器，`VeraPerf`）：方块面板第一次 build->draw 211 ms，之后每次 87 ms（input->draw 116 ms）。

翻页（PageScrollView，只在方块风格）：分组框里的每一行也算一个条目，翻页停在行的边上；这一屏最下面显示不全的那一行用白色盖住（它是下一页的第一行）；
页数和当前页按真实的翻页位置算（以前按高度除，带半行时会多算或少算一页）。

共用的东西都在 `Blocks.java`：`activityHead` / `headInto`（方块页头）、`restyle` / `restyleTop`（把“大标题 + 列表 + 底部返回”的老页面换装）、`paged`（整页翻 + 翻页条）、
`PagedList`（一页整数行的分页列表）、`listRow`、`sectionTitle`、`sep`、`boxed`；`Ui.frame` / `Ui.button` / `Icons.Toggle` 在方块风格下直接画成直角框和方框开关，
所以各个页面里的按钮、分段（`Seg`）、开关不用一个个改。

## 盖在应用上面的设置（SettingsActivity）

下拉面板的 设置（经典面板的 全部设置）、宿主的 settings 动作不再切回桌面：打开 `SettingsActivity`——自己的任务
（taskAffinity `com.veradroid.home.settings`、不进最近任务、NEW_TASK），盖在当前应用上面。方块风格是“设置”（和“我的”同一页，
没有底部标签，右上角 ✕），经典风格是经典设置分类（顶栏多一个 ✕）。子页面返回一层一层退；根页按返回或点 ✕ 就关掉，原来的应用
还在原来那一页（模拟器上 EinkBro 进程号不变）。从设置里再开的 Wi-Fi、统计等页面在这个任务里，返回回到设置。
代码上它就是 HomeActivity 的 standalone 模式（同一套 BlocksHome / BlocksSettings / fillSettings），只搭“我的”和点开的设置页，
不预先搭别的页、不挂小部件宿主、不做桌面那些事（继续阅读截图、检查更新、书库扫描……）。桌面“我的”标签里的设置照旧。

## 界面字重（2026-11-14：默认用跟设计风格接近的粗体）

我的 → 显示与刷新 → 界面 → **界面字重**：常规 / 中粗 / 粗（键 `ui_weight`，默认 粗），只管方块风格下 VeraHome 自己的界面（阅读器正文、经典风格不变），改了当场重搭，不用重启。
- 粗：英文数字 Amazon Ember Bold（标题 Heavy），中文华文黑体 STHeitiBold；中粗：Ember Medium / Bold + STHeitiMedium / Bold。
  都是 Kindle 自己的字体，运行时从 `/data/media/0/KindleFonts`（宿主只读绑的 `/usr/java/lib/fonts`）读，不拷进镜像和仓库。
  Android 镜像里只有 Roboto Regular / Bold 和单字重的 DroidSansFallback，没有真的中文粗体；读不到 Kindle 字体时退回 Roboto Bold + 描粗的 DroidSansFallback。
- 选了“系统字体”（霞鹜文楷、系统黑体、导入的字体……）时用它：粗体角色描粗（Skia fake bold），“粗”档正文也描粗；小字号上描粗只多一像素，看起来比真粗体细。
- Ember 的行高比 Roboto 大，用这套字时去掉字体自带的上下留白（includeFontPadding=false），页面高度和以前差不多。

别的应用的系统字体变粗（没做）：要在 Android 启动前由宿主把改过的 `/system/etc/fonts.xml`（sans-serif 400 → Roboto-Bold，中文后备 → 华文黑体）绑上去，
或者把 Kindle 的字体文件绑到 `/system/fonts` 的同名文件上；关掉就是下次启动不绑，能还原，但要改宿主脚本、重启 Android 才生效，
而且字形宽度变了，有的应用（排版写死宽度的）会截字，需要逐个应用测。

## 结构（代码）

| 文件 | 内容 |
|---|---|
| `Blocks.java` | 共用控件：直角黑框卡片、黑底标题条、英文小字、步进器 `Stepper`、方块级别条 `BlockBar`、分段 `SegBar`、翻页条 `Pager`、底部导航 `Nav`、统计格 |
| `BlocksHome.java` | 外壳（顶上一行时间 / 电量、底部 首页 / 文件 / 应用 / 我的）、首页卡片、应用、我的 |
| `BlocksFiles.java` | 文件：最近 / 书籍（按文件夹）/ 图片 / 笔记（书签），分页 |
| `BlocksSettings.java` | 我的 → 首页卡片 / 显示与刷新 / 电源与时间 / 存储与连接 / 设备与关于 |
| `BlocksCards.java` | 卡片的数据：第三方应用的最后画面、天气、日历缓存、每日诗词、Android 小部件宿主 |
| `Lunar.java` | 农历（系统 ICU 的 ChineseCalendar）和二十四节气（太阳黄经低精度公式），全在本机算 |
| `ReaderActivity.java` | 方块风格时：点屏幕中间出顶栏（返回、章名、时间、电量）和底部 目录 / 字体 / 排版 / 显示 / 模式 / 系统，各开一张设置单；“正在打开”卡片 |

每个标签和设置页都是一棵完整的控件树，挂在同一个 FrameLayout 下只换可见性；每页记一个“签名”（用到的数据），签名没变直接换上去，
变了在显示之前同步重搭——和经典风格一样，换页面只刷一次。主页闲下来时把四个标签先搭好、量好、画一遍（字形进缓存）。

## 首页卡片

我的 → 首页卡片：开关、上下移动（键 `blk_cards`，逗号分隔，默认 `continue,stats,recent`）。放不下一屏时分页翻。

| 卡片 | 数据 |
|---|---|
| 继续阅读 | 内置阅读器上次读的书（封面、进度、章名 `ch:<路径>`、格式 · 大小 · 时间）**和**最近用过的第三方应用（图标、名字、“上次使用 x 分钟前”、离开时的画面缩略图），哪个更近哪个在上，另一个在下面一行。点按接着读 / 回到那个应用 |
| 阅读统计 | 本周阅读时长（`Stats`，周一起）、书签总数 |
| 最近阅读 | 三本书的封面和进度，“全部 ›”进 文件 → 最近 |
| 时钟与日期 | 大字时间 + 日期、星期、农历、节气；每分钟只改这一行字 |
| 日历 | 本月，格子里是农历日 / 初一写月份 / 节气，今天黑底；每月算一次缓存 |
| 天气 | 来源可换（`BlocksCards.WeatherSource`）：默认 wttr.in，取不到再试 Open-Meteo；城市手动输入，只把城市名发给 Open-Meteo 的地名搜索查经纬度，之后只发经纬度；一小时最多取一次、只在 Wi-Fi 开着并回到首页时取，失败不提示；统一格式缓存在偏好 `wx_norm`，卡片底下写来源（署名）和“更新于 / 离线 · 上次更新”。2026-11-13 实测：两处不同的网络上 api.open-meteo.com 的天气接口超时、地名搜索可用，wttr.in 可用 |
| 每日诗词 | `assets/poems.txt`（和开机画面同一份），按日期轮换 |
| 快捷应用 | 自己挑的最多 5 个应用（键 `blk_quick`） |
| Android 小部件 | `AppWidgetHost`（宿主 ID 0x5648，平台签名有 `BIND_APPWIDGET`）；高度 小 / 中 / 大；应用推来的更新合并成至多一分钟一次，没有布局动画 |

**第三方应用的画面怎么来的**：显示桥的共享缓冲 `/dev/kfb/fb`（两页 RGBX，Android 的逻辑尺寸）里留着刚离开的应用最后画的画面。
离开主页去开应用时，主页从两页各抽一张小灰度图（180 像素宽）；回到主页的那一刻（自己还没画）再抽一次，变了的那一页就是应用的画面，存成
`.vdhome/state/cache/lastapp/thumb.png`。只读像素，不读别的应用的数据库，不知道它读到哪一页。从 VeraHome 自己的页面（阅读器、统计…）回来不算。

## 设置页（我的）

- **显示与刷新**：亮度 / 暖光（方块级别条，宿主的 `light` / `warmth` 命令，机器没有暖光就不显示）、刷新档位 跟随 / 流畅 / 均衡 / 画质（宿主 `KFB_SMOOTH` 0–3）、
  刷新方式（`KFB_MODE`）、全刷周期（`KFB_FLASH`）、对比度、反色、立即整屏刷新、翻页动画（`KFB_ANIM_MODE`）、应用字号（`FONT_SCALE`，`AppFont.setUser`）、每个应用的显示效果、界面风格、动画、下拉面板的快捷开关（`quick`）和面板名称（`panelname`）、英文小字；更多显示设置 → “显示与刷新”的全部设置。
- **电源与时间**：自动休眠（`sleeptime`）、回到 Kindle 的方式（`RETURN_MODE`）、回 Kindle / 重启 / 关机、切换应用、清理后台；时间制式（`TIME_12_24` + 桌面的 `clock12`）、时区和日期（只读：跟 Kindle 同步）。
  参考视频里的“自动关机”和“设日期”我们没有：Android 跑在 Kindle 里，日期和关机归 Kindle。
- **存储与连接**：存储用量、存储空间页、Wi-Fi、已保存的网络、蓝牙翻页器、DNS（经典页）、网页传书（Web 文件管理）开关和地址 / PIN。
- **设备与关于**：机型、系统、版本、内存；检查更新、使用统计、问题反馈；设备与更新、手势、应用与桌面（壁纸 / 图标 / 面板）、传书、全部设置 → 对应分类的方块设置页，返回时回到这一页。

## 阅读器（方块风格）

点屏幕中间一块（横竖各中间三分之一 / 一半）出顶栏和底部六个按钮，再点正文收起。设置单盖在正文上，同一时间一张：

- **目录**：目录 / 书签，一页 6 条，当前章黑底。
- **字体**：字体步进器（点中间的名字出一页 6 个的选择表）、字号 14–40。
- **排版**：行距、段距（新）、左右边距、首行缩进（新，0 / 1 / 2 字）、对齐。段距和缩进只加排版标记，不改文字，书签和续读的字符位置不变；改了以后按字符位置重新分页。
- **显示**：刷新档位（全局 `KFB_SMOOTH`）、全刷周期、极简全屏（不显示页脚）。参考里的“笔记虚线”没有：我们的阅读器还没有笔记 / 划线。
- **模式**：反色、翻页动画、点按翻页（左边上一页 / 全屏下一页）。
- **系统**：书签、跳转、整屏刷新、下拉面板、回到桌面、回 Kindle。
- **正在打开**：方块风格下第一页最多等 1.5 秒（经典 4 秒）；第一页及时排好时卡片根本不画出来，慢的时候先出一张“正在打开”卡片，字排好后收起。

## 外观（第二版，按用户“要那种有边框的”）

所有方块都是直角黑框 + 右下方实心黑投影（`Blocks.Frame`，纯黑不是灰色渐变）；主卡片（继续阅读、设备卡、文件列表、设置列表）是双线框；
步进器的值是黑底白字，两边是方框箭头；开关是方框开关（开 = 右边实心方块）；分段、翻页条、路径条都带框带投影；底部导航当前标签上面一条短粗黑线。
“继续阅读”一行固定成封面的高度：左边带框的封面（或第三方应用离开时的画面），右边顶上黑底“继续阅读”，下面书名、读到、章名、格式·大小·时间，最底下“百分比 … 时间”和带框的进度条；没有在读的书时同样的框、封面位置留白。

## 耗时


耗时（`VeraPerf` build->draw，Windows 主机上的模拟器 pw6-5182-win，PW6 5.18.2 + VeraDroid 0.89 宿主）：
- 方块：四个标签之间来回 12–65 ms（每轮第一次进“文件” 107 ms），我的 → 五个设置页 30–62 ms、返回 15–43 ms；
- 同一台模拟器上经典风格 主页 ↔ 书库 10–78 ms，两者在一个量级；
- 第一次切换到方块风格（冷：类加载、第一次排版）模拟器上 3.3–3.8 s，之后闲下来时把四个标签和五个设置页预先搭好。
- 第三方应用的画面：离开主页 / 回到主页时从 `/dev/kfb/fb` 各抽一张 260 像素宽的灰度图，回主页那一次在第一帧之前做完。
- 冷光 / 暖光：宿主命令 `light N` / `warmth N` → `lipc-set-prop com.lab126.powerd flIntensity / currentAmberLevel`，在 PW6 模拟器上核对过（18→6、0→9）。
- 天气：模拟器网络里 wttr.in 能取到（杭州 17°）；wttr.in 的 lang_zh 常是英文，改成按 WorldWeatherOnline 天气代码自己翻成中文。
- 小部件：用 `tools/testwidget`（只用于验证的最小小部件 APK）绑定成功，`dumpsys appwidget` 里宿主是 com.veradroid.home，卡片里显示了它的内容。
- 节气算法核对：2026 年 24 个节气的日期和公布的一致（小寒 1/5 … 冬至 12/22）。

已知问题：
- 模拟器上 VeraHome 出现过一次 ART JIT 编译器自身的断言（`assembler_thumb2.cc:236 src_end == dest_end`，Jit thread pool），进程由系统拉起后正常。
  用 `dalvik.vm.extra-opts=-verbose:jit -Xjitthreshold:30` 在 Windows 模拟器上把各页面、阅读器、设置单反复走了一遍（55 次 JIT 编译，含 OSR），没有复现；
  dex2oat `--compiler-filter=everything` 全部方法编译也不触发。`-verbose:jit` 会在编译前打“Compiling method …”，下次复现时就能知道是哪个方法。
- 1072×1448 等尺寸是用 `wm size` 在 PW6 模拟器上模拟的，不是那几个机型的真模拟器。

## 第三轮（2026-11-14）：美观、功能、墨水屏动画

**功能**
- 文件：搜索、排序（名称 / 时间 / 大小）、多选（批量移动 / 删除，都要确认）；长按一个文件可以 打开 / 重命名 / 移动到 / 删除。
- 笔记：每个书签单独一行，点了直接打开到书签那一页（做法是把续读位置改成书签的位置，阅读器还是只刷一次）。
- 阅读器：目录单里加了“跳到”（5% 一步的步进器，点中间的值输入页码）；排版单加了 紧凑 / 标准 / 宽松 三档预设；字体单写明怎么导入字体（Fonts 文件夹）。
- 首页：长按卡片可以 上移 / 下移 / 移除 / 管理；横屏时两栏；“全部”进新的“全部书”页（封面格子，可按 最近 / 书名 / 作者 / 最近添加 排序，分页）。
- 我的：一排快捷设置（Wi-Fi、亮度、整屏刷新、动画档位）。
- 应用：排序按钮；长按可以置顶、隐藏（“显示隐藏的”可以找回）。
- 继续阅读：只认阅读应用。默认名单：微信读书、KOReader、Moon+、多看、掌阅、Kindle、番茄等；EinkBro 这类浏览器不算。名单可以在“首页卡片”里改（键 `blk_readers`）。
- 空状态、读取中都画成带框的图标 + 标题 + 说明；方块风格下对话框也是直角双线框。

**墨水屏动画**（我的／显示与刷新／动画：关 / 简洁（默认）/ 完整）
- 换标签、进出设置页：显示桥的 `SWIPE <方向> <步数>` 一次性命令，让 MTK 控制器做硬件擦除。简洁 2 步，完整 3 步；中间帧是控制器自己的快刷，最后一帧是 GLR16，不闪。
- 阅读器设置单打开 / 收起：上 / 下擦除。翻列表：简洁 1 步，完整 2 步。
- 完整档另外有：按下的方块立刻反色（DU 小块），抬手还原；新加的卡片第一次出现时反色闪一下。
- 显示桥改动（`display/epd.c`，`host/pw6|k49/bin/veradroid-epd` 已重编）：`SWIPE` 原来会改掉用户的 ANIM 方向 / 步数，现在是真正的一次性命令。
  它有自己的方向和步数，ANIM 关着也能用，800 ms 内没有新画面就作废。没有别的地方用这个命令，经典风格不受影响。
- 实测（Windows 主机上的模拟器，PW6，`VeraPerf` input->draw）：四个标签来回切换，关 35–119 ms，简洁 27–129 ms，完整 30–101 ms（第一次进一页、冷启动的那次除外），没有多出整屏闪刷。
  模拟器上只有约一半的切换真的走了擦除，其余的照常用 REAGL 刷，原因还没查清，需要在真机上看。
